Bounded JVM-free NeoForge/Fabric JAR adaptation, external shaderpack planning, and declarative Magic/VFX/Animation/Combat-Motion engines are implemented. Implemented components and boundaries

Native simulation paths

Rust systems cover selected Create kinetics, belts, fluids, and culinary data. The supported behaviors and workloads are still being checked against Minecraft and mod implementations.

Client and rendering work

The client implements protocol probing, Magic/VFX/Animation/Combat-Motion handling, and shaderpack capability planning with conservative fallback. The isolated client-gpu crate has a real winit + wgpu window and offscreen rendering, with a recorded non-blank Vulkan offscreen frame on AMD RX 7800 XT (RADV).

Automatic mod adaptation at boot

The mods/ startup scan skips a catalog of 52 superseded performance mods and attempts bounded data, culinary, and Mixin lifting through live_mod_bridge / auto_adapter. Unsupported code is classified for fallback or quarantine.

Standalone CLI binaries

The five tools are mc-spine (server), mc-spine-client (client utilities), mc-spine-mod-check (inspect/adapt/scaffold), mc-spine-world-migrate (1.21.1 ↔ 26.3), and mc-spine-init (server setup with explicit EULA acceptance).

Mod adaptation and native authoring

Put existing NeoForge or Fabric JARs in mods/ for automatic startup inspection. The Rust live_mod_bridge / auto_adapter can skip superseded performance mods and lift supported data, culinary, and Mixin patterns without launching a JVM.

Automatic boot-time classification

Supported JAR contents can become native bundles or bounded lifted shims. Unsupported Tier 3 Java/Mixin behavior is reported for fallback, delegation, or quarantine; arbitrary existing mods are not guaranteed to run.

Native mods without a JVM

Authors can use mc-spine-mod-check --scaffold-native to generate a validated mc-spine-mod-bundle/1 starter. This declarative format supports native authoring; additional mod data and behavior must still be implemented.

Read the mod and shaderpack author guide →

External shaderpack formats and native WGSL

The Alpha parses user-provided shaderpacks and plans pipelines against GPU capabilities. No third-party shaders are bundled. Unsupported GPU features select a safe built-in rendering fallback in the planner.

Classic OptiFine and Iris

Classic OptiFine GLSL 120–330 passes are recognized. The Iris 1.7–1.11+ specification covers GLSL 430–460 compute shaders, SSBOs, images, and dual-hand uniforms.

DistantHorizons LOD and Megu WGSL

DistantHorizons LOD stages include dh_shadow, dh_terrain, and dh_water. Native WGSL packs use megu-shader.toml with explicit pass declarations and .wgsl files.

Shaderpack support currently covers parsing and fallback planning. A real winit + wgpu GPU client exists; live third-party shaderpack visual fidelity and server/modpack interoperability remain unverified.

Start a server with explicit EULA acceptance

1. Initialize for 1.21.1 and accept the EULA explicitly
mc-spine-init --dir ./server --mc-version 1.21.1 --accept-eula
2. Optionally scan the mods/ folder without a JVM
mc-spine-mod-check --scan-mods-dir ./server/mods
3. Start the server from its directory
cd ./server && mc-spine
All six mod-check modes, 26.3 initialization, world migration and client ping 
# Initialize a 26.3 server (requires explicit EULA acceptance)
mc-spine-init --dir ./server-26.3 --mc-version 26.3 --accept-eula

# Six mutually exclusive mod-check modes
mc-spine-mod-check --modpack ./pack.mrpack
mc-spine-mod-check --scan-jar ./mods/example.jar
mc-spine-mod-check --scan-mods-dir ./mods
mc-spine-mod-check --adapt-jar ./mods/example.jar --out ./adapted
mc-spine-mod-check --adapt-mods-dir ./mods --out ./adapted
mc-spine-mod-check --scaffold-native my_mod --out ./my_mod.bundle.json

# Inspect or migrate a world between 1.21.1 and 26.3
mc-spine-world-migrate inspect-anvil ./world
mc-spine-world-migrate migrate-level --in ./world/level.dat --out ./converted-level.dat --to 26.3

# Ping a running server
mc-spine-client --ping localhost:25565

Current status

Available in Alpha

  • Vanilla 1.21.1 protocol, online-mode AES-CFB8 auth, and Velocity modern forwarding
  • Deterministic worldgen, random ticks, villagers, commands, ops/bans/whitelist, RCON, and async backups
  • Twelve standalone crates (eleven without third-party dependencies and isolated client-gpu), plus five CLI tools for server, client, mod inspection/adaptation, world migration, and setup

Still in progress

  • Full Vanilla parity across general-seed worldgen and gameplay interactions
  • Native Anvil live world storage and broader live modpack execution
  • Third-party shaderpack visual fidelity, live modpack E2E, and wider GPU hardware/platform coverage
