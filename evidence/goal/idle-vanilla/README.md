# 目標の最初の測定：vanilla との同条件比較（アイドル）

**この枝で初めて、別実装（vanilla 本体）と条件を揃えて測った。**
再現：`bash tools/idle_compare.sh 12 0`

## 条件（goal が挙げる4つを揃えた）

| 条件 | 値 |
|---|---|
| seed | **0**（両方） |
| ワールド種別 | **flat**（両方。理由は下記） |
| view-distance | **4**（両方） |
| simulation-distance | **4**（両方） |
| プレイヤー | **0人**（両方） |
| 測定窓 | 起動完了後 **12秒**、`/proc/<pid>/stat` の utime+stime |

vanilla は公式 1.21.1 バンドラ（`server.jar`、SHA-1 `59353fb4…`、マニフェスト照合済み）。
バンドラはライブラリを自己展開するので、環境に無い jopt-simple 等を用意する必要がない。

## 結果（連続測定）

| idle 12s | CPU (s) | RSS (MiB) | threads |
|---|---|---|---|
| vanilla 1.21.1 | **0.320** | **987.5** | 62 |
| **mc-spine** | **0.000** | **5.2** | 3 |

別の実行では vanilla が 715.5 MiB / 0.310s だった（JVM の warmup で変動する）。
桁で言えば **メモリ約 1/140〜1/190、アイドルCPUゼロ**。

## なぜこれは「条件を揃えた」と言えるか

アイドル・プレイヤー無しでは、**vanilla は依然としてスポーンchunkを tick し、
完全なworld状態とJVMを保持する**。mc-spine はどちらもしない。
つまり「誰も居ないときに何をするか」という**同じ問い**に両方が答えており、
片方だけが値を出しているのではない。

## 示すこと / 示さないこと

**示す**：同seed・同ワールド種別・同視野/シミュレーション距離・プレイヤー無しで、
mc-spine のアイドル RSS と CPU が vanilla より桁で小さい。

**示さない（重要）**：
- **同じ仕事をしている比較ではない。** mc-spine は実装している機能が**少ない**。
  差の一部は「安くやっている」ではなく **「やっていない」**である。
- **プレイヤーが居る状態の比較ではない。** chunk送信・entity追跡・戦闘は測っていない。
- **worldgen の比較ではない。** mc-spine は worldgen datapack が無いため
  `[wg] worldgen datapack missing — flat generator` で **flat** を生成した。
  vanilla も flat に揃えた（揃えなかった場合、vanilla 側だけが地形を持つ）。
- **機能あたりの費用ではない。** 実装済みの部分（炉・水・ホッパー）は
  [recipe-cache](../time-contract/recipe-cache/README.md) の x2.52 のように
  前後比較でしか測っていない。

## この測定が変えたこと

計画の「実環境計測の手段」が **存在する**ようになった。次に必要なのは
**同じ仕事をさせた比較**（プレイヤーを入れ、同じ構造を置き、同じtick数だけ走らせる）で、
それは「機能あたりの費用」を主張するための前提である。
