# tick周期とtick確率の網羅監査

## なぜ

飛翔体TTLが3例目の同じ種類だったので、**網羅的**に洗い直した。
今度は「減算されるtickカウンタ」を手がかりに、保持値と周期の両方を見た。

## さらに4件見つかった

| 対象 | 旧 | 4TPS | 20TPS | 種類 |
|---|---:|---:|---:|---|
| 飢餓ダメージ | `t % 16 == 8` | 4s | 0.8s | 周期 |
| 溶岩/流体scheduled tick | `TICK_IDX % 6` | 1.5s | 0.3s | 周期 |
| 雨の発生確率 | `% 6000 == 0` | 1/24000 每秒 | 1/3000 每秒（**8倍**） | tick確率 |
| Mob湧み確率 | `% 400`, `% 32` | 1/2000 每秒 | 1/250 每秒（**8倍**） | tick確率 |

雨と湧みは**周期ではなく確率**なので、割るのではなく**掛ける**。
`TICKS_PER_SECOND` を掛けて每秒の確率を保つ。
ここを間違えると8倍の頻度になる。周期と逆方向。

## 修正

- 周期: `server_ticks(STARVE_GT=80)`、`server_ticks(FLUID_TICK_GT=30)`
- 確率: `RAIN_CHANCE_DENOMINATOR = 6000 * TICKS_PER_SECOND / 4`
- 確率: `MOB_SPAWN_CHANCE_DENOMINATOR = 400 * TICKS_PER_SECOND / 4`

`/ 4` は「4TPSの値からの相対」であり、`old * new_tps / old_tps` と同じ。

## 監査で除外したもの

- `plate_powered` の `st % 2` — ブロック状態のbit判定
- `rand_u64() % 8` — 乱数、tickと無関係
- `% 5`, `% 6`, `% 23`, `% 601`, `% 197`, `% 89` — ブロック状態符号化とworldgen
- `% 5 == 0`（b.age のアイテム選択）— tick周期ではない

## 残る未監査

- `bs[i].1`（雷の寿命）は変換済み
- `hurt_at` 500ms は実時間なので周期非依存
- `shield_cd` 5s は vanilla も5s
- **戦闘の `invulnerableTime` 20 相当ロジックは未実装**

## 教訓（4例目）

同じ種類が4回出た。検索は「tickカウンタの減算」を手がかりにすると抜けが減る。
`-= 1`・`+= 1` されるフィールドを洗い、その初期化と閾値を確認する。
