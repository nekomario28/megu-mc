# サーバー単体の起動・アイドル計測（vanilla比較ではない）

## 何を測ったか

releaseビルドの `mc-spine` を**空の一時ディレクトリ**で起動し、
listener ready までと、その後12秒間のRSS・CPU・スレッド数を測った。

| 項目 | 値 |
|---|---|
| listener ready | 検出限界以下（接続が即成功） |
| 起動直後のRSS | **5.1 MiB** |
| アイドル12秒のRSS | **5.3–5.6 MiB** |
| CPU (utime+stime) | **0 ticks / 約12秒** |
| スレッド数 | 3 |

CPUが0 tickというのは「12秒間に10ms未満」の意味。tickの粒度が10msなので、
アイドルCPUは最大でも約0.08%。

## 測っていないもの（重要）

- **vanilla実サーバーの測定は存在しない。** 比較は一切できない。
  「vanillaより軽い」という主張の根拠はこの記録に無い。
- 空ワールド・プレイヤー0。実運用の負荷ではない。
- ワールドオーバーレイを読込んだ状態のRSS。`world()` は変更セルだけを持つ
  疎なマップなのでワールド規模に比例して増えるが、**その増加を測っていない**。
- チャンク読込・view/simulation distance を変えたときのRSS。
- 起動時間（worldgenを含む実ワールドのロード）。
- GC/アロケータの挙動、断片化、長時間稼働での増加。

## RSS の意味

`VmRSS` は共有ページ（libc等）を含む。プロセス固有のメモリではない。
複数プロセスを並べた合計とは一致しない。

## 参考：計測用fixtureのRSS（サーバーではない）

`evidence/time-contract/*/results.json` の peak RSS は
**releaseテストバイナリ**のもの。15回の測定で14.6–14.9 MiB。
稼働炉400・Actor100・Mob600等を含むfixtureで、サーバー本体の値ではない。

## この記録で言えること / 言えないこと

- 言える: mc-spineは空ワールドで 5.3–5.6 MiB RSS、アイドルCPUは実質0。
- 言えない: vanillaとの比較、実負荷での軽量性、ワールド規模に対する増加。
