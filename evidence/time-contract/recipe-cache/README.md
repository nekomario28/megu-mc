# smelt 解決のキャッシュ — end-to-end 測定

この枝で**初めて**、最適化を fixture の tick で前後測定した記録。
測定は**連続**（同一マシン、同じ座席で before → after）。

## 方法

`active_furnaces_pack` は datapack の精錬レシピを**40件**読み込むシナリオ。
一致しないレシピなので、キャッシュが無い限り**炉ごと・tick ごとにリスト全体を走査**する。

**before の作り方が肝**。最初は `smelt_out` 全体をキャッシュから外したところ
`active_furnaces`（datapack無し）まで 100倍になり、**忠実でなかった**。
本来キャッシュされていた**不変側（組み込み）の memo まで外れていた**ため。
可変リストの走査**だけ**を外し、組み込みは現行と同じくキャッシュを通す形に直した。
`idle_furnaces` が 0.98x のままなのが、その対照になっている。

## 結果（release、2 run 平均）

| シナリオ | tick 前 (ns) | tick 後 (ns) | **tick 比** | 炉stage比 |
|---|---|---|---|---|
| `active_furnaces`（datapack無し） | 16,722 | 15,069 | **x1.11** | x1.32 |
| `active_furnaces_pack`（40レシピ） | 38,037 | 15,098 | **x2.52** | x5.11 |
| `idle_furnaces`（対照） | — | — | **x0.98** | — |

- **40レシピで tick が x2.52** — 主張の閾値 x1.10 を大きく上回る
- **datapack無しでも x1.11** — レシピが空でも毎回 `json_smelts()` の mutex を
  取っていた費用が消える
- `idle_furnaces` が x0.98（=変化なし）であることが、
  「測っているのは炉の仕事だけ」であることの対照

## この測定が示すこと、示さないこと

**示す**：datapack の精錬レシピがあるとき、炉stageの費用とtick全体が
上表の比で小さくなる。等しい20TPS・等しい世界・等しい負荷で、前後を連続測定した。

**示さない**：
- **vanilla との比較ではない。** この比は「この枝の前後」であって
  「vanilla より軽い」ことの証明ではない。
- **代表負荷ではない。** 400炉・1プレイヤーの合成シナリオである。
- **実クライアントでの確認ではない。**
- この fixture は worldgen を無効化している。
