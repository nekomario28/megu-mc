# 自己レビュー（独立レビューが不通の間の代替）

## 位置づけ

独立レビュー（`codex review`）は外部の利用制限で9slice連続で不通。
ユーザー指示により、自分で未レビュー範囲を確認した。
**独立レビューの代替ではなく、同等の権限の証拠ではない。**

## 発見1（実バグ、修正済み）: air供給が6箇所で4TPSリテラルのまま

`server_ticks(300)` への変換はslice 08で行ったが、**リセット経路2箇所だけ**だった。
生成経路6箇所は `air: Mutex::new(60)` のまま。

4TPSでは 60 tick = 15s で正解。20TPSでは 60 tick = **3s**。
新規参加プレイヤーと湧いたMobの空気が3秒になり、即座に溺死し始める。

修正：`AIR_SUPPLY_GT = 300` を名前付き定数にし、全8箇所がそこから導出する。

これは slice 09 がreceiptに書いた
「呼び出し側のliteralは行動ゲートで検出できない」限界の**2例目**。
1例目は溶岩ダメージ。どちらも検索でしか見つからない。

## 発見2（限界の再確認）: 検索以外に発見手段がない

変換クラス全体を `rg` で洗い、今回が最後だと確認した。
残る `t % 2 == 0` は1件のみで `plate_powered` のブロック状態bit判定。
tick除算ではないので対象外。

意図的に残した実時間境界：
`hurt_at` 500ms（被ダメ無敵）、`shield_cd` 5s（vanillaも5sなので一致）、
`last_hit` の「ずっと前」sentinel、雷の `lh.elapsed()`。

## ゲート

`air_supply_is_derived_everywhere_a_creature_is_constructed` が
定数の実時間と、生成経路のairが導出値であることを検証。
負の対照：`AIR_SUPPLY_GT` を 60 に戻すと `60 vs 300` で失敗。

serial/parallelとも32 passed・1 ignored。Fabric/NeoForge checkも合格。

## レビューできなかったこと

- vanilla実サーバーとの動的tick比較（実行環境がない）
- 実クライアントでの描画・操作
- 戦闘・ダメージ経路の全数値検証
- 負荷下のtick遅延と超過時の挙動
- 移動・衝突の詳細（vanilla係数に替えたが照合相手がない）

これらは静的検査でも自分レビューでも証明できない。
