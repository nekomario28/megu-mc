# 空inputの炉のrecipe lookupを省く

## 等価性の根拠

`furnace_tick` は毎tick、warmな全炉についてrecipeを引いていた。
`out` が読まれるのは `input.1 > 0` のときだけである。

- `can_smelt` は `f.input.1 > 0 && out...` なので、`input.1 == 0` なら `out` は評価されない
- 精錬分岐は `can_smelt` を通るので、そこでも `out` は読まれない

したがって `input.1 == 0` のとき `out` を計算しないのは**同一の結果**を生む。
炉の状態・産出・xp・乱数消費は変わらない。キャッシュの中身だけが変わりうるが、
`CachedLookup` は入力が同じなら同じ値を返するので観測可能な差はない。

## 測定（同一fixture・同一runner・release・各3プロセス、HEADを基準）

| fixture | tick 比 | furnaces stage 比 |
|---|---:|---:|
| 空 | x1.00 | x0.99 |
| idle Actor 1 | x1.00 | x1.01 |
| 休止炉400 | **x1.20** | **x1.57** |
| 稼働炉400 | x1.01 | x1.02 |
| 同chunk Actor 100 | x1.00 | x1.01 |
| 密集 Actor 100 | x1.00 | x1.04 |

プロセスCPU合計 0.2760–0.2791s → 0.2722–0.2733s。

全fixtureで後退なし。休止炉400個ではtick全体で1.20倍、炉stageで1.57倍。
実サーバー全体の性能やvanilla比較の証明ではない。

## 残る大きい候補（未実装）
