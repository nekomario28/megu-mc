## #21 — two behavioural fixes

1. **`nextInt(bound)` threshold.** The modern/Xoroshiro rejection threshold was
   `(bound.wrapping_neg() as u64) % bound`, which sign-extends `-bound` before the
   remainder. 1.21.1 uses `Integer.remainderUnsigned(~bound + 1, bound)`, a
   32-bit unsigned remainder. The code now computes
   `u64::from((bound.wrapping_neg() as u32) % (bound as u32))` and keeps the
   Lemire multiply-high/shift result. The old threshold is harmless for
   power-of-two bounds and wrong for many others on the rare redraw path.
2. **Biome tree ties.** `BT::search` sorted children by distance and pruned
   before visiting them. Vanilla `SearchTree.TreeBranchNode.getResultingNode`
   scans children in **array order**, descends only when the incumbent is
   strictly farther, and replaces only on a strictly smaller distance. Equally
   near leaves therefore resolve to the incumbent/first-reached leaf. The sort
   and the root early return are gone; the test corpus is tie-heavy.

## #24 — lazy tracing

`dtrace`/`rtrace` now accept `impl Display`, so `format_args!` is formatted only
after the existing enabled/armed check. `src/trace_env.rs` caches `env_flag!` and
`env_str!` once per call site. This changes only debug output timing: a variable
set after a site's first check is not observed, as documented in the PR. No
performance improvement is claimed here; this slice did not benchmark it.

The new `trace_env` module required a layer-policy entry. It is a leaf utility;
`feature`, `worldgen` and `main` may use it, `generation_context` does not in the
actual graph. The current graph is **20 modules / 47 edges / 0 named errors**.

## Independent reference checks

The PR test vectors are inputs, not trusted answers. Both were replayed against
the pinned 1.21.1 jar through ordinary constructors/API:

- **`nextInt`**: `tests/data/random_next_int_1211.tsv`, **1,116 rows**, all three
  generators (`Xoroshiro128PlusPlusRandom`, `WorldgenRandom`, legacy
  `LegacyRandomSource`) and 31 bounds. All hashes and following `nextLong`
  values match (`tools/nextint_oracle.py`).
- **Tie tree**: `tests/data/biome_probe_ties_1211.tsv`, **2,500 rows / 2,287
  tie-flagged**. The actual `Climate` parameter tree is searched with the
  thread-local previous result cleared before every point, as the upstream
  extractor does; all 2,500 answers match (`tools/biome_tie_oracle.py`).
  Without clearing the previous result, 5 rows differ, which is why the oracle
  explicitly clears it.

The committed vectors were generated by the upstream PR's `tools/vanilla_data`
extractor, which is not present on this branch. Independent replay is the
provenance evidence for this import; regeneration is not claimed.
