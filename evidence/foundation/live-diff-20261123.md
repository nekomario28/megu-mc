## Diffs that are real bugs (same trace, same world semantics)

### BUG-LD1 — stale-then-new block update on single break (block_break)
Position `(6,240,1)`: megu sends `[state=1(stone)]` then `[state=0(air)]`.
Vanilla sends only `[state=0]`. The pre-change state is re-emitted to clients —
one wasted packet per break plus a visible 1-frame flicker of the old block.

### BUG-LD2 — exact-duplicate block update (slab_step_up)
`setblock … stone_slab` produces the SAME update payload `11225` twice on megu,
once on vanilla. Together with LD1 this is a systematic **over-notification
family**: block-change emission lacks delta dedup.

### BUG-LD3 — redundant full-window `container_set_content` per slot delta
crafting_planks `place_ingredient`: megu emits `0x13×3 + 0x15×2`; vanilla emits
`0x15×2` only. Same for `store_planks` (megu `0x13×2+0x15` vs `0x15`) and
`take_result` (megu `0x13×3+0x15×3` vs `0x15×3`). Each `0x13` resends the whole
window — O(window) bytes per O(1) change, on every click/craft.

### BUG-LD4 — chunk under-delivery: 25 vs 45 chunks on join
Same client view request; megu active chunks 25 (5×5 square), vanilla 45
(~7×7 minus corners / larger radius semantics). Players see a smaller world
than vanilla for the same settings. Needs ChunkWindow radius/geometry check.

### BUG-LD5 — advancements payload 1417 B vs vanilla 274 B on join
Different sha (megu `6c1301ff…`, vanilla `b073af8b…`). megu emits ~5× the
advancement bytes — extra entries/criteria vanilla doesn't send on join.
