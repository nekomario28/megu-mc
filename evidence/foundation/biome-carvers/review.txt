### 1. `carver_lists_match_the_pinned_biomes` cannot distinguish "empty list" from "biome absent"; the loader drops the six empty biomes — `src/generation_contract_tests.rs:510`, `src/feature.rs:4234-4243`, `src/feature.rs:4223`

`let got = reg.biome.get(name).cloned().unwrap_or_default();` accepts a biome that was never inserted as `[]`. That is not hypothetical here: the six "empty" fixture entries are `"carvers": {}` in the pinned jar/pack (`datapacks/vanilla/data/minecraft/worldgen/biome/the_end.json`, `the_void.json`, `end_*.json`), and `carver_list` returns `None` for an object without an `air` key, so `load_creg` never inserts those six (registry has 58 entries, not 64). A regression that drops a biome entry for any reason (parse failure at `feature.rs:4222`, `carver_list` returning `None`, or an unknown step key) is invisible for exactly those six, which contradicts the stated invariant in `specs/done/biome-carvers/README.md` ("空・欠落・未知carverを「carverなし」と混同しない") and the evidence claim "compares every list" (`evidence/foundation/biome-carvers/README.md:43-44`). Fix: return `Some(vec![])` for the object form when the AIR step is absent (reporting an unrecognised step key the way `p_carver` reports unsupported carvers), then assert presence in the test (`assert_eq!(reg.biome.get(name), Some(&want))`, optionally `reg.biome.len() == 64`). Behaviour of `apply_carvers` is unaffected (absent == empty for AIR), so this is a gate/invariant defect, not a carving defect.

### 2. `pack_cf` fallback precedence is inverted relative to the production loader — `src/generation_contract_tests.rs:1236` (and the claim at `evidence/foundation/biome-carvers/README.md:30-32`)

The loader is `Gen::dp_files_any(&["configured_feature", "feature"])` (`src/feature.rs:2265`, `src/worldgen.rs:496-504`: "later *names* winning within a pack"), i.e. **`feature` overrides `configured_feature`**. `pack_cf` tries `configured_feature` first, so in a converted pack that ships both directories the dripstone/root/rooted-azalea tests pin the config production does *not* load — the helper's own comment ("the pack it is actually running on") is then false. Latent today (the bundled pack has 0 files under `worldgen/feature/`), but it is the exact scenario the fallback was added for. Fix: iterate `["feature", "configured_feature"]`, or read through the loader's merge helper so the precedence cannot drift.
