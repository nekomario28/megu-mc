# 保存の構造と、参照先の存在

`schema.py` を `schemagx inspect` すると節の依存構造を検査できる。
これは記述したモデルの検査であり、実データの参照先が存在することや、
並行する保存が原子的なスナップショットを取ることの証明ではない。

世界は生成結果へ重ねる疎なオーバーレイ。保存された行がないことと、
実際のセルが空気であることは違う。コンテナの所有者は `block_at` の答えで判定する。
チェストストアには樽とシュルカーボックスも入るため、チェスト連結の判定を
全コンテナの存在判定へ使わない。

## 実装を通す検査

保存の試験は `src/persistence_tests.rs` と `src/tick_tests.rs`。
破壊された所有者と生存する所有者を同時に用意し、保存後に対象ストアを消去する。
ロード後は、生存側のブロックと中身・状態が正確に復元し、破壊側が復活しないことを検査する。
ローダが何もしない変異、チェスト・炉・看板の掃除を失う変異は必須ゲートが検出する。

ローダは多数の共有ストアと導出索引を触るため、保存試験は `test_support` により
独立したテストプロセスで実行する。親のストアへ一部だけを戻すfixtureを使わず、
成功・assert失敗のどちらでも親の世界は変更されない。子プロセスには実行期限がある。

この検査は逐次入力の保存・復元を保証する。並行更新とのスナップショット整合性は
別の契約であり、この試験の緑から推論しない。
