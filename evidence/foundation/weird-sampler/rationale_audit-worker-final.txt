### Actionable issues (low severity — scope/precision, no false claim found)

1. **Scope blast radius not stated.** `normal_new_amps` is the shared constructor for *every* `firstOctave/amplitudes` noise, not just the three sampler noises: `datapacks/.../noise/temperature.json`, and by the same encoding `continentalness`/`offset` (used as fixtures in `tools/weird_sampler_oracle.py`) are all routed through it. So the repair also shifts climate-noise consumers (spline/biome and surface temperature), which inv-5 explicitly leaves unaccepted. The doc says "限定契約" and "無関係なconverted/legacy経路の振る舞いを維持します" — both true, but a reader can read the seam as cave-sampler-only. Suggested clause: the native constructor is shared, so non-sampler native noises change too and are outside this acceptance.
2. **Pointer precision (inv-4).** Cite `eval0_c` (or "`eval_c`/`eval0_c`") as where the sampler is evaluated; keep `eval_c` only as the interpolation-context/cache seam.
3. **Duplicate contract copy / asymmetric 正本 chain (outside the audited file).** `specs/weird-sampler/README.md` still exists with different wording, and `evidence/foundation/weird-sampler/README.md` back-links to that path, not to `specs/done/weird-sampler/README.md`. The audited file's own links are correct; the reverse link is not (it would dangle if the in-progress copy is removed). Worth aligning before the evidence README is treated as canonical.

**Verdict:** all rationale claims in `specs/done/weird-sampler/README.md` are supported within its stated bounded local scope, modulo the three precision items above. Static audit only — no runtime verification was performed.
