## 2. evidence-producing path の修復（なぜ）

旧 readiness runner は `cargo ... -v` の `Executable` 行を grep で拾っていた。拾えないと
`"" --list` が exit 127 になり、`bin=` / `sha256=` が空、`tests_total=0` のまま「成功した receipt」が
残った（`<cache>/mc-spine-readiness/logs/main.out`）。数値を書いたことではなく、
**測定不能を PASS として emit したこと**が欠陥。

追加したもの（小さく、既存の入口を使う）:

- `tools/evidence_receipt.py`: Cargo の JSON から binary を解決（grep しない）、binary の存在・
  非空・SHA-256、`--list` の exit と test 数、指定 filter の「1件以上 passed / 0 failed」、
  start/finish の HEAD と dirty patch hash の不変、`--expect-head` 一致を全て満たしたときだけ
  `status=PASS`。1つでも欠ければ `FAIL` で exit 1。
- `tools/cargo_executable.py`: `cargo test --no-run` の harness（`test:true`）と `cargo build` の
  binary（`test:false`）を別関数に分離。従来は harness を解決できず、これが空 binary の一因。
- `tests/evidence_receipt_test.py`: 旧 observed shape を固定する firing guard（8 cases）。
  executable 無し / `--list` exit 127 / 0 tests / 0 passed（park） / red filter / stale HEAD が
  **FAIL すること**、正の対照が PASS することを assert。`tests/verify.sh` の gate 群に追加。
- `tools/mutation_check.sh`: `MUTATION_LOG_DIR` で mutant の失敗 assertion と restored control を
  保存（従来は caught の log を捨てていた）。
