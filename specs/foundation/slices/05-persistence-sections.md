# 05 — 永続化の section 登録

## Why

保存は約15節の**手書きの順序**で、各節が裸の `write_varint(len)` を書く。
読込は同じ順序で読み、**46箇所の `if p < payload.len()` / `if p + N > len { break }`**
で守っている。

    // furnaces are block entities — ...
    // sheared-mob indices ...
    // scoreboard — ...
    // drop despawn-budget residue ...
    // weather is world state ...
    // entity tags ...
    // scheduled functions ...

### 順序が暗黙の契約になっている

節の位置は「コード上の並び」でしか決まらない。途中に節を1つ挿すと、
**以降の全節がずれる**。しかも読込側のguardは
「データが尽きたら黙って `break`」なので、**壊れた保存を検出せず
部分的なワールドで起動しうる**。

グローバルな envelope（SPN4）は全体のtruncationを検出するが、
**節のずれや節内のfield追加はずれのまま通る**。

### 節ごとの版が無い

MET4 は**グローバルな**版。個別の節に field を1つ足すと、
同じ節の中の以降の読み取りがずれる。節ごとに版を持つ場所が無い。

### 新しい状態を持つ部品ごとに、同じ手作業が要る

slice 02（queue）や 04（entity framework）を入れると、
予約済みtick・エンティティ種が新しい状態になる。
そのたびに「節を1つ足し、順序を合わせ、guardを書く」手作業が発生する。

## 契約

**節が自分を登録し、順序は registry が持ち、節ごとに版と長さを持つ。**

```rust
trait SaveSection {
    fn id(&self) -> SectionId;         // 順序は id の順に固定
    fn version(&self) -> u32;
    fn write(&self, out: &mut Vec<u8>);
    fn read(&mut self, body: &[u8], version: u32) -> Result<(), ReadError>;
}
```

- 各節は **`(id, version, length, body)`** として書く。本体は**長さで区切る**。
  → 未知の節は**長さぶん読み飛ばせる**。将来の節追加が旧サーバーを壊さない。
- 節内のfield追加は**節の version を上げる**。
  `read` は version を見て解釈する。グローバルな MET4 に依存しない。
- 節の順序は `SectionId` の順に固定。**手書きの並びをやめる。**
- 読込は `Result` を返す。**節が途中で切れていたら起動を中止する**
  （既存の「壊れた保存なら起動しない」方針と一致）。
- 既存15節の**バイト列は変えない**（本体の内容はそのまま）。
  外枠だけ `(id, version, len)` を付ける。

## 非目標

- 保存形式をAnvil/region化すること（issue #3 の P3。別段階）。
- 節の並列書込・差分保存。まず**構造**を入れる。
- 既存節の中身の整理。slice 03/04 が済んでから。

## ゲート

- **往復の等価性**: 既存の保存ファイル（合成fixture）を読んで書き直し、
  **本体のバイト列が同一**であることを検証する。
- **前方互換**: 未知の `id` を持つ節を含む保存を、**読み飛ばして**起動できる。
- **節の版**: 節の version を上げた保存を、旧 version の読み手が
  その節だけ既定値で読む（または明示的に失敗する）ことを検証する。
- **順序の独立**: 節を1つ挿した保存でも、他の節が影響を受けない。
- **破損**: 節長が本体と合わない保存は**起動を中止**する。
- 全テスト、CI 4step、wire smoke。

## リスク

- 既存の46個のguardを一度に外すと、壊れた保存の扱いが変わる。
  **節ごとに移し、その都度「壊れた保存で起動しない」テストを回す。**
- 長さ前置きにすると保存が数十バイト増える。無視できるが記録する。
- 節の登録漏れ。登録し忘れた節は書かれず、**無言でデータを失う**。
  登録を1箇所に集め、既知の節IDを列挙するテストを置く。
