# 13 — 20TPS切替（不可分）

## 状態: 実行済み（`bf2c595` 以降）。このsliceは当初の実行計画であり、以下はその内容。

前提（slice 05–12）が揃った。残るは `TICK_MS = 50` への**1コミット**。
约束により分割有効化は禁止。中途半端にtickだけ速くすると移動・効果・機械が
5倍速で走り、結果が壊れる。

## この1コミットで変えるもの

### 1. 周期
```rust
const TICK_MS: u64 = 50;   // 250 -> 50
```
`TICKS_PER_SECOND` は 20、`GAME_TICKS_PER_TICK` は 1 に自動的に変わる。
`server_ticks(gt)` は `gt / 1 = gt` になる。**保存値は全てvanilla game tick値と
一致する**。slice 05–12で導出済みなので、追加の定数変更は不要。

### 2. 効果の保存持続（server tickとしての値が変わる）

`Eff.left` はserver tick。4TPSの `180` は45s。20TPSでは45s = 900。
**vanilla game tick値を `server_ticks()` で包む**ことで切替後も45s。

- トーテム: 再生 `server_ticks(900)` / 吸収 `server_ticks(100)` / 火炎耐性 `server_ticks(800)`
- 金リンゴ: 吸収 `server_ticks(480)` / 再生 `server_ticks(20)`
- エンチャント金リンゴ: `480` / `80` / `1200` / `1200`
- 腐肉・鶏: `120`、フグ: `60` / `60` / `240`、蜘蛛の目: `20`

**wire変換は消える。** `e.left * GAME_TICKS_PER_TICK` が `* 1` になるので
`e.left` をそのまま送ればよい。二重単位が解消される。

### 3. 効果の周期

vanillaは `50 >> amp`（再生）・`25 >> amp`（毒）・`40 >> amp`（ウィザー）。
現在は4TPSに合わせて半分にしている。`server_ticks()` で包む。

- 再生: `server_ticks(50) >> amp`（現在10、20TPSで50）
- 毒: `server_ticks(25) >> amp`（現在5）
- ウィザー: `server_ticks(40) >> amp`（現在8）
- 空腹の消耗: `e.left % server_ticks(80)`（現在80）

### 4. 移動係数をvanillaへ（**結果が変わる**）

一次証拠（`AbstractArrow.javap.txt:747` が `0.99f`、`:665` が `0.05d`、
`ThrowableProjectile.javap.txt:163` が `0.99f`、`aZ()` が `0.03d`）から確定。

| 対象 | 現在（4TPS, gravity-lite） | vanilla（per game tick） |
|---|---|---|
| 弓矢 抗力 | `dx * 0.9` | `* 0.99` |
| 弓矢 重力 | `dy -= 0.02` | `-= 0.05` |
| 投擲（パール等） 抗力 | `dx * 0.7` | `* 0.99` |
| 投擲 重力 | `dy -= 0.05` | `-= 0.03` |
| 釣針 | `dx * 0.6`, `dy -= 0.04` | 一次参照で確定が必要 |

vanillaは水中で抗力 `0.8f`（`ThrowableProjectile.javap.txt:156`）。
現在の実装は水中分岐を持たない。これも同時に必要。

**これは近似からの脱却であり近似化ではない。しかし弓矢・パール・Mobの軌道が変わる。**

### 5. TTL（**結果が変わる**）

一次参照の結論：弓矢の1200は**inGround消滅カウンタ**であり、生成からの飛翔ttlは
存在しない。投擲弾にも固定飛翔ttlは無い。

| 対象 | 現在 | vanilla |
|---|---|---|
| 弓矢 ttl | 240（60s） | 飛翔ttlなし。接地後1200 |
| Mob弓矢 ttl | 160（40s） | 同上 |
| パール ttl | 50（12.5s） | なし。衝突条件のみ |
| 釣針咬み | `age > 15`（3.75s） | 待機100..600、接近20..80、咬み20..40 |

期限でのパールテレポートは独自挙動。撤去するとエンティティが蓄積するため、
inGround/衝突ベースの消滅を同時に実装する必要がある。

### 6. 天候の範囲

`RAINING` は現在 `server_ticks(12000)` = 下限固定。vanillaは12000..24000。
`THUNDERING` は `server_ticks(3600)` = 下限。vanillaは3600..15600。
発生判定も `wrapping_mul % 6000` という近似。範囲と乱数消費をvanillaに合わせるかを
別途決める。これは切替と独立に修正できる。

### 7. 液体tickとobserver

`TICK_IDX % 6`（溶岩）とobserverの6tick。vanillaはランダムtick。
game tick周期として扱えるか一次参照で確認する。

## 永続化の帰結（切替と同時に決める）

旧MET3ファイルのdrop ageはミリ秒として書かれている。現在のloadはtick数として
読む。切替後は1tick=50msなので、旧ファイルの `300000` は300000 tick（15000s）になり
即座に消滅する。**MET4化してversionを明示し、旧形式はmsとして読む**ことを推奨する。
実データが無いため影響範囲は不明。判断が必要。

## 有効化後の主張の境界

20TPSになっても「超軽量」は主張できない。同一20TPS・同一機能・同一seed・
同一距離・同一負荷での測定が必要。vanilla実サーバーとの動的tick比較も未実施。
