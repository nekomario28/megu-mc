# 01 — トーテム付与集合の修正

## 契約・範囲

死亡保護の付与関数は、既存効果を全て除去し、再生II900・吸収II100・耐火I800の
vanilla game tick相当の効果だけを作る。現在の4TPSでは180/20/160 server tick。
20TPSへ移行するときはこの保存語とテストも同時に変える。

根拠は親specの一次証拠、LivingEntity.checkTotemDeathProtection。
通常経路と効果tick中の発動は同じ `totem_effects(&mut Vec<Eff>)` を使う。
IDは既存 `name_to_effect` の名前解決を使い、別のID表を導入しない。

このパスは付与集合だけを修正する。HP・アイテム消費・ダメージ順序・吸収プール・
効果パケット送信の完全性・20TPS化は後続ゲート。ここで全体互換を主張しない。

## 検証

実際にproductionから呼ばれる付与関数へ、毒・別の再生・重複した吸収を持つ入力を与える。
出力集合を種類/amp/実時間相当の持続まで固定値で比較する。再度付与しても重複しない。
vanillaは先にremoveAllEffectsなので、無関係な既存効果を残すテストにはしない。

まず旧コードで失敗することを確認し、修正後に同じテストを通す。
次に既存の全Rustテストを実行し、必要ならJava機能のコンパイルも確認する。
コマンドはリポジトリ直下で `cargo test --offline --locked -j 2 -- --test-threads=1`。

## レビュー上の制約

既存の効果更新の反復中にVecを変更しない。期限切れ効果の除去はトーテム再付与より前に
行い、旧効果の期限切れで新しく付与された効果を消さない。
最初の検証は付与関数の結果だけ。ネットワーク通知の一致とは別に記録する。

許される内部判断はテストの置き場所・命名のみ。結果・定数・除去方針は委譲しない。
