# 28 — 実際にプレイする観点での不足一覧

「Minecraftとして遊ぶときに足りないもの」を棚卸しした。
**方法はコード読解による調査であり、実プレイではない。** 網羅は主張しない。
各項目に「確認方法」を付ける。数えただけの項目は数えたと明記する。

## A. 明確に無い（コードで確認）

### A1. 次元が無い（Nether / End）

`nether_portal` `end_portal` `end_portal_frame` `end_gateway` は
**ブロック状態IDとしてのみ存在**（`state_to_item` の表）。

確認: `rg -n 'nether_portal|end_portal'` の一致は全てID表の行。
ポータル起動・次元移動・ディメンション切替のコードが無い。

影響: ネザー要塞・ブレイズロッド・エンダーパール入手経路・エンドラ戦が存在しない。

### A2. レッドストーンの伝達部品が無い

| 部品 | 状態 |
|---|---|
| レバー | **動作する**（`name == "lever"` の処理あり） |
| レッドストーントーチ | ID表のみ |
| **レッドストーンダスト（wire）** | **ID表のみ。信号伝達なし** |
| **リピーター** | **ID表のみ** |
| **コンパレーター** | **ID表のみ** |
| ピストン・オブザーバー・ディスペンサー・ホッパー・感圧板・ドア | 動作する（`redstone_update` / `piston_*` / `observer_tick` 等） |

確認: `redstone_wire` の一致2件、`repeater`/`comparator` 各2件はいずれも
`state_to_item` / `item_to_state` の表。`redstone_update` はドア等の
6近傍処理で、距離を伝わるネットワークではない。

影響: **離れた部品を配線できない。** レバーの隣でしか動かない。
ピストンドア、隠し扉、自動化の大半が作れない。

### A3. 村人・村・取引・襲撃が無い

`villager` の一致は spawn_egg、effect名、sound名のみ。
`open_merchant` フィールドはあるが、村人は湧かず取引も無い。

確認: `rg -ni 'village|raid'` の一致に村人生成・取引生成のコードが無い。
`trades` 関数はあるので窓の実装は部分的な可能性がある（未確認）。

影響: エメラルド経済・エンチャント本の取引・経験値源が無い。

### A4. ビュー距離が固定（±4チャンク＝81チャンク）

`stream_chunks` の窓は `for dx in -4..=4` 固定。
クライアントの描画距離設定を受けず、運営者も変えられない。

確認: `stream_chunks` の範囲定数。設定用の環境変数も見当たらない。

影響: 見える範囲が狭い。遠景が消える。MODの「描画距離を上げる」も効かない。

### A5. Mob の種類が少ない

`name_to_etype` は **130エントリ**（スポーンエッグ/コマンド用の名前表）だが、
`mob_tick` に挙動があるのは **5種**：chicken(19) / creeper(23) /
skeleton(91) / spider(100) / zombie(124)。他に15(cat)・72 の参照がある。

確認: `mob_tick` 内の `m.etype` 分岐は32箇所だが、対応する種は上記のみ。
自然湧きも `match attempt % 5` で同じ4種（夜の敵対Mob）。

影響: 牛・豚・羊・鶏（鶏は有）などの家畜、村人、ウォーデン、ピリジャー等が無い。
食料・羊毛・革の入手が spawn_egg か `/give` に依存する。

## B. 部分的 / 近似（確認済みだが範囲未特定）

- **ワールド生成**: 独自のノイズ・樹木・鉱石・構造物。vanillaのseed一致は未検証。
  「vanillaと同一の地形」という主張はできない。
- **エンチャント**: レベル・競合・EPF・`enchant_applicable` は実装。
  エンチャントテーブルの窓も `open_table` で開く。ただし
  候補生成・ラピス消費・シード依存のばらつきは未確認。
- **ポーション**: `potion|brewing|cauldron` の一致12件。醸造台の実装は未確認。
- **天候**: 雨・雷・落雷はある。雷の持続は雨と別値に修正済み。
- **釣り**: 待機・咬み・引き寄せはある（TTLは実時間維持の独自値）。

## C. この調査の限界

- **実プレイしていない。** コード読解による帰結のみ。
- 「一致件数」で判断した項目がある。名前表と実装の区別は
  主要なものだけ個別に確認し、全部は見ていない。
- クライアント側の描画・操作（インベントリ操作の手触り、クラフトUI、
  チャット表示等）は**一切検証していない**。実クライアントでの確認が必要。
- パケットの網羅性は確認していない（未知パケットへの応答等）。

## D. 優先順位の提案（遊ぶ目的による）

1. **レッドストーンの配線**（A2）— サバイバルで最も早く詰まる
2. **ビュー距離の設定**（A4）— 体験の質に直結。運営者向けの設定が要る
3. **家畜と食料**（A5）— サバイバルの基本ループ
4. **村と取引**（A3）— エンチャント・エメラルドの供給源
5. **次元**（A1）— 規模が最大。最後

いずれも「時間契約」とは独立で、このbranchには含めない。
