# 最終目標への計画

Status: 計画。数値はすべて実測で、測っていないものは「未測定」と書いてある。

この文書は**現在地から最終目標までの道**を示す。個々の slice の設計は
[foundation](foundation/README.md) / [gameplay](gameplay/README.md) /
[time-contract](time-contract/README.md) / [mod-compatibility](mod-compatibility/README.md) が持つ。
ここが持つのは**順序・合格条件・証拠の要求**だけである。

## 1. 最終目標と合格条件

**目標**：Minecraft Java 1.21.1（protocol 767）の**超軽量**サーバで、
**観測可能な挙動は vanilla のまま**、必要な Mod も使える。

**「達成した」と言うために必要な測定**（現在、このうち満たしているものは無い）：

| # | 合格条件 | 測定方法 | 現状 |
|---|---|---|---|
| G1 | **同じ仕事**で軽量である | vanilla と mc-spine を**同一 seed・同一 view/simulation distance・同一負荷**で走らせ、CPU 時間とメモリを比較 | **未測定**。あるのは**アイドル時のみ**（vanilla 2.690 s / 1094.3 MiB / 63 threads 対 mc-spine 0.000 s / 30.1 MiB / 3 threads）。**負荷が違うので軽量の証拠にならない** |
| G2 | **同じ結果**である | 同一入力列に対する結果（ブロック・アイテム・RNG消費・保存状態）が一致する | **未測定**。機能単位の門はあるが、**vanilla との突き合わせは無い** |
| G3 | **20TPS を守る** | 負荷時に tick が 50 ms を超えない | **未測定**。時間契約（slice 01〜14）は完成し、`bf2c595` で切替済み |
| G4 | **playable** である | 実クライアントが接続し、描画・移動・破壊設置・戦闘ができる | **未測定**。`tests/wire_smoke.py` は**スクリプトであり実クライアントではない** |
| G5 | **挙動が vanilla** である | 要素ごとの一致（下記フェーズで積む） | **部分**。エンティティ型 4%、レッドストーン伝播なし、ディメンションなし |

**この5つのうち G1〜G4 が未測定であることが、現在の最大の穴である。**
機能を足すほど「軽量」の主張は検証から遠ざかる。

## 3. フェーズ

各項目に**証拠の要求**を付ける。証拠が出ない項目は完了にしない。

### フェーズ 0：目標を測定可能にする（最優先）

**理由**：G1〜G4 が未測定のまま機能を足すと、「軽量」も「vanilla 準拠」も
**反証不能な主張**になる。機能追加より先にここを埋める。

| # | 項目 | 成果物 | 証拠の要求 |
|---|---|---|---|
| 0.1 | **実クライアント検証** | vanilla 1.21.1 クライアントが接続し、地形が見え、歩け、ブロックを壊せ、チャットできる | スクリーンショットと、クライアント側ログに protocol error が無いこと。**`wire_smoke.py` はこれの代わりにならない** |
| 0.2 | **代表負荷の定義と固定** | 「代表負荷」を数値で定義（チャンク数・エンティティ数・レッドストーン素子数・炉/ホッパー数・プレイヤー数）し、fixture 化 | 定義と fixture がリポジトリにあり、誰でも同じ負荷を再現できる |
| 0.3 | **同一仕事での vanilla 比較** | G1 の測定 | seed・view/sim distance・負荷を揃えた**前後比較**。揃えられない項目は明記して除外理由を書く |
| 0.4 | **結果一致の突き合わせ** | G2 の測定（同一入力列 → 保存状態の差分） | 差分があれば**許容した差分として列挙**し、それぞれ理由を書く |
| 0.5 | **性能の CI ゲート** | 退行を検出する | **壁時計は CI で不安定なので使わない**。命令数など決定論的な計数にする |

**0.1 を最初にやる。** クライアントが繋がらないなら、他のすべての測定は土台を失う。

## 4. 横断的な規律（フェーズに関係なく守る）

1. **資産が registry**。手書き表を書く前に `tools/asset_coverage.py` を走らせる。
2. **ガードは落ちられることを証明する**。`tools/mutation_check.sh` にエントリを足す。
   **落ちられないテストはテストが無いより悪い。**
3. **測ってから変える**。back-to-back の前後比較、ノイズ床 4%、
   **x1.10 未満は主張しない**。**測定を無効化されたら取り下げを書く。**
4. **計測器が自己矛盾したら計測器を疑う**。
5. **レビューは実質的な変更につき1回**、範囲を固定した問いで。effort を選び、既定で最大を費やさない。
6. **1コミットずつ、各段で検証**。`verify.sh` は `&&` で連結する。
7. **`main` へそのままマージしない**（issue #7 REQUEST CHANGES が未解決）。

## 5. リスクと未知

| リスク | 影響 | 手当て |
|---|---|---|
| **実クライアントが繋がらない** | G1〜G4 の土台が崩れる | 0.1 を最初にやる |
| **代表負荷が現実を代表しない** | 軽量の主張が空虚になる | 0.2 で数値を固定し、後から変えたら**前の測定を無効化する**と書く |
| **座標・時間契約がディメンションで崩れる** | Nether の 8倍換算は既存の座標系に触る | 5.1 の前に時間契約の門を再走させる |
| **`pblocks.json` と `blocks_1211.json` が別バージョン** | 2/1060 が対応しない | 対応しないものを列挙して理由を書く（1.7） |
| **未取得の独立レビュー** | 統合時の衝突解消に独立確認が無い | フェーズ 1 の後にもう一度、範囲を固定して取る |
| **「バニラ準拠」の主張が定義されない** | G5 が永遠に未達 | 0.4 で**許容する差分を列挙する**ことを合格条件にする |

## 6. やらないと決めたこと

- **一般化したスケジューラ**を、名前の付いた消費者が現れる前に作らない。
- **並行した世界/効果の状態**を作らない。
- **設定モードを増やさない**。
- **Pumpkin / Starlight / Lithium / FerriteCore のコードと文面を写さない**
  （設計と挙動は参照する）。
- **`black_box` をコンテナに当てて中身を読ませようとしない**。
- **静的 `javap` を実行時測定の代わりにしない**。

## 7. 未解明の欠陥（計画より先に片付ける）

### 落下テストが並列実行で落ちる（原因未解明・主張を2度反転させた）

**症状**：落下を使う3テストが `--test-threads=8` で**4回連続して失敗**（100 passed / 3 failed）。
`air` があるべき位置にある（=砂が消えている）。

**再現**：

| 実行 | 結果 |
|---|---|
| 全スイート `--test-threads=1` | **103 passed** |
| 全スイート `--test-threads=8` | **100 passed / 3 failed**（4/4 回） |
| フィルタ `fall` `--test-threads=1` | **3 passed / 3 failed** |
| フィルタ `sand_falls` 単独（`--nocapture` で状態を出力） | 列もキューも**正しく見える** |

**世界を書き換えるテストでロックを取っていないものは、機械的な走査では見つからなかった。**

**まだ説明できていないこと**：
1. 単独実行で失敗するのに、状態を出力すると正しく見えること
2. `--nocapture` の有無で見え方が変わること（レースの可能性）
3. フィルタ実行（1thread）でも3件落ちること — スレッド競合だけでは説明できない

**この欠陥について2度主張を反転させた。** 最初に「8threads で決定論的に失敗する」と書き、
「変異が適用されたままのツリーだった」として撤回し、その後 4/4 失敗で**撤回の根拠が誤り**と分かった
（古いバイナリを測っていた）。**計測を毒したままの主張と、正しい主張の撤回の両方を経験している。**

**次の一手**：`old_falling` の復元・`forceloaded` の復元・テスト領域の復元が、
**どのテストの後にどの値を期待するか**を1テストずつ出力して突き合わせる。
`--nocapture` で挙動が変わることが本当なら、**レースである**と確定できる。

**それまで、このスイートが緑であることに依存しない。**
